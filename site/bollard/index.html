Bollard is the wall.

A bollard is a fixed post. It does not negotiate. Six PreToolUse hooks can deny a write. Ran is not the same as fired. Fired on a test fixture is not the same as fired on a registered project. The Quality Bar's 3-of-6 mixed those. The ledger does not.

5/6deny on a registered project cwd (architecture, goals-freeze, preflight, concept, dep-prov)
1/6ship_readiness: 3 denies, all one scratchpad path
6/6have run. Each has thousands of silents except concept, which still has thousands.
ATLASrun 4 clean. v_gate_proven_live trust_state=ok.

What the ledger actually shows

architecture_gate, goals_freeze_gate, and preflight_blocking_gate were already live in the Quality Bar snapshot. concept_gate has since denied on FORE and HYPHY. dependency_provenance_gate still spends most of its fires in its own test fixture (39 of 56), but it also denied on HYPHY and SELFTEST. ship_readiness_gate has three fires, all under a /private/tmp scratchpad. That last one still has not met the bar.

What this is not

These counts are ATLAS v_gate_proven_live after ingest run 4 (clean: 19 checks, 0 contract failures). A hook that only ever denies inside its test suite is still an untested hook wearing a passing suite. ship_readiness is in that bucket. dep-prov is no longer fully in it.

What holds across all six

Every hook decision, fired or silent, lands in one ledger. A compliance cron re-judges those decisions on a schedule. One dated pass judged 95 hook-firing events: 7 compliant, 26 genuinely non-compliant, 60 dismissed. That is one pass, not a settled rate. The scorer behind it has a documented 3.4x swing across passes with no changelog explaining the swing. Treat the breakdown as a snapshot, and treat dismissed as dismissed by that pass of that scorer.
